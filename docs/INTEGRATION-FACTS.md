# QuickBooks Online and Xero: verified integration facts

Date checked: 2026-10-28.

Method note: the official developer portals (developer.intuit.com is a JavaScript app, several developer.xero.com pages return only a title) did not render fully through our fetch tool. Facts below come from official-domain pages as surfaced by search excerpts plus the one Xero page that rendered in full (faq/limits). Anything not read directly on an official page is marked UNVERIFIED. Re-check the linked page before quoting a number in client-facing material. Intuit and Xero change limits and pricing tiers; do not put raw numbers on marketing pages that could go stale.

Status key: CONFIRMED = read on an official page. SNIPPET = official page excerpt via search, not read in full. UNVERIFIED = not confirmed on an official page.

## QuickBooks Online (Intuit)

| Topic | Fact | Status | Source |
|---|---|---|---|
| OAuth | OAuth 2.0 authorization code flow. The redirect returns an authorization code and the realmId (company ID) used in API URLs. | SNIPPET | https://developer.intuit.com/app/developer/qbo/docs/develop/authentication-and-authorization/oauth-2.0 |
| Scope | Accounting scope is `com.intuit.quickbooks.accounting`. | SNIPPET | https://developer.intuit.com/app/developer/qbo/docs/develop/authentication-and-authorization/oauth-2.0 |
| Refresh token life | 100 days, rolling (extended on use). | SNIPPET | https://developer.intuit.com/app/developer/qbo/docs/develop/authentication-and-authorization/faq |
| Refresh token rotation | Intuit may return a new refresh_token value when you refresh; always store the latest values from the most recent response. | SNIPPET | https://developer.intuit.com/app/developer/qbo/docs/develop/authentication-and-authorization/faq |
| Rotation interval | Third parties say about every 24 hours. Not confirmed on an official page. | UNVERIFIED | n/a |
| Access token life | 3600 seconds (1 hour). Seen in third-party guides and Intuit SDK samples; not read on an official page here. | UNVERIFIED | https://developer.intuit.com/app/developer/qbo/docs/develop/authentication-and-authorization/oauth-2.0 |
| Throttling | 500 requests per minute per realm ID (production); 10 requests per second per realm ID and app; HTTP 429 `ThrottleExceeded` (code 003001) on breach; Intuit advises waiting 60 seconds before retry. Sandbox limits are lower and the docs say so. | SNIPPET | https://developer.intuit.com/app/developer/qbo/docs/learn/limits-and-throttles ; https://help.developer.intuit.com/s/article/API-call-limits-and-throttling |
| Batch | Batch endpoint: 120 batch requests per minute per realm (Aug 2025 update); Intuit pages disagree on payloads per batch (30 recommended on the limits page, 10 in an older best-practices article). Requests over 120 seconds time out. | SNIPPET, partly conflicting | https://developer.intuit.com/app/developer/qbo/docs/learn/limits-and-throttles ; https://help.developer.intuit.com/s/article/QuickBooks-Online-API-Best-Practices |
| Query page size | Max 1000 entities per query response; paginate with STARTPOSITION/MAXRESULTS. | SNIPPET | https://developer.intuit.com/app/developer/qbo/docs/learn/limits-and-throttles |
| Change data capture (CDC) | Returns entities changed since a `changedSince` timestamp. Look-back must be within 30 days; max 1000 objects per request; results grouped by entity type; deleted objects listed after active ones. | SNIPPET | https://developer.intuit.com/docs/api/accounting/changedatacapture |
| Webhooks | JSON POST notifications (CloudEvents structure available) carrying entity name, ID, operation and realmId; one notification can batch events for several companies. Only companies that authorized the app via OAuth 2.0 send notifications. Pattern: treat webhook as a trigger, then fetch the entity by ID. | SNIPPET | https://developer.intuit.com/app/developer/qbo/docs/develop/webhooks/configure-webhooks |
| Webhook gaps | Developer-forum reports say some indirect changes (for example a payment applied to an invoice) may not emit a webhook for every affected entity. User reports, not official policy. Mitigation: periodic CDC reconcile. | UNVERIFIED | https://help.developer.intuit.com/s/question/0D54R00008c36frSAA/quickbooks-webhook-is-not-pushing-events-regarding-indirect-edits |
| Webhook signature header | `intuit-signature` (HMAC-SHA256 with verifier token). | UNVERIFIED (not read here) | https://developer.intuit.com/app/developer/qbo/docs/develop/webhooks |
| Optimistic locking | Every entity has a `SyncToken`, incremented per modification; updates with a stale SyncToken fail. Sparse updates (`sparse=true`) change only the fields sent. | SNIPPET | https://developer.intuit.com/app/developer/qbo/docs/learn/explore-the-quickbooks-online-api |
| Entities | Accounting API includes Invoice, Bill, Payment, BillPayment, Customer, Vendor, Account, Item, JournalEntry, TaxCode and others. | SNIPPET | https://developer.intuit.com/app/developer/qbo/docs/api/accounting/all-entities/invoice |
| Sandbox | Separate Development keys and sandbox companies; sandbox base URL is `https://sandbox-quickbooks.api.intuit.com`; OAuth 2.0 Playground can issue sandbox tokens. Production realm IDs do not work against the sandbox host. | SNIPPET | https://developer.intuit.com/app/developer/qbo/docs/develop/authentication-and-authorization/oauth-2.0-playground |
| Production keys | Production client ID/secret are issued only after the app assessment questionnaire is completed and approved, even for apps not listed in the App Store. App Store listing/review is a separate, optional step. | SNIPPET | https://help.developer.intuit.com/s/article/New-app-assessment-process-FAQ ; https://developer.intuit.com/app/developer/qbo/docs/go-live/publish-app |
| Pricing / metering | Intuit App Partner Program classifies APIs (Core / CorePlus) with variable platform fees; metering of some calls (CDC among them) changed in 2025. Check current terms before scoping a client's volume. | SNIPPET | https://blogs.intuit.com/2025/08/13/upcoming-changes-to-the-accounting-api/ ; https://help.developer.intuit.com/s/article/API-classification-for-the-Intuit-App-Partner-Program |
| Multi-company | Each QuickBooks company is a separate realmId with its own tokens; one app can hold many realm connections. | SNIPPET | https://developer.intuit.com/app/developer/qbo/docs/develop/authentication-and-authorization/oauth-2.0 |
| QuickBooks Desktop | Not covered by the Online REST API. Desktop integration uses a different mechanism (Web Connector/SDK). Not researched here. | UNVERIFIED | n/a |

## Xero

| Topic | Fact | Status | Source |
|---|---|---|---|
| OAuth | OAuth 2.0 authorization code flow; PKCE flow available for native/SPA apps; Custom Connections use client credentials (single organisation, premium, limited regions). | SNIPPET | https://developer.xero.com/documentation/guides/oauth2/auth-flow/ ; https://developer.xero.com/documentation/guides/oauth2/pkce-flow ; https://developer.xero.com/documentation/guides/oauth2/custom-connections/ |
| Access token life | 30 minutes. | SNIPPET | https://developer.xero.com/documentation/guides/oauth2/auth-flow/ |
| Refresh token | Issued only if `offline_access` is requested; valid up to 60 days from last use; each refresh returns a new refresh token and the old one stops working, except a 30-minute window in which the previous token can be retried if the response was lost. After 60 unused days the user must re-authorize. | SNIPPET | https://developer.xero.com/documentation/guides/oauth2/auth-flow/ ; https://developer.xero.com/documentation/guides/oauth2/token-types/ |
| Tenants / connections | A user can authorize several organisations; the app calls the connections endpoint to list tenant IDs and sends `xero-tenant-id` on each API call. | SNIPPET (header name from memory of docs, page not rendered) | https://developer.xero.com/documentation/guides/oauth2/tenants |
| Rate limits | Per tenant: 5 concurrent calls, 60 calls per minute, 5000 calls per day. App-wide: 10,000 calls per minute across all tenants. HTTP 429 with `Retry-After` header; remaining-quota headers `X-DayLimit-Remaining`, `X-MinLimit-Remaining`, `X-AppMinLimit-Remaining`. Limits are the same for all apps and cannot be raised on request. | CONFIRMED (page read) | https://developer.xero.com/faq/limits |
| Connection caps | Apps start on a Starter tier (5 connections); Core 50; higher tiers more. Apps on Plus and above must be certified; App Store listing requires Plus or above. | SNIPPET | https://developer.xero.com/documentation/guides/oauth2/limits/ ; https://developer.xero.com/documentation/xero-app-store/app-partner-guides/faqs/ |
| Uncertified apps | Each Xero organisation can connect at most five uncertified apps; no limit on certified apps. (An earlier internal note of "25 connections" was not confirmed; 25 appears only in a partner PDF about premium-tier features.) | SNIPPET | https://developer.xero.com/documentation/guides/oauth2/limits/ ; https://developer.xero.com/documentation/best-practices/managing-connections/connections/ |
| Scopes | Granular accounting scopes (for example `accounting.invoices`, `accounting.payments`, `accounting.banktransactions`, `accounting.contacts`) replace broad `accounting.transactions`. Apps created on or after 2 March 2026 use granular scopes; existing apps have until September 2027. Granular scopes do not include journals access (connections from 29 April 2026). | SNIPPET | https://developer.xero.com/documentation/guides/oauth2/scopes/ ; https://developer.xero.com/faq/granular-scopes |
| Incremental sync | `If-Modified-Since` header (UTC timestamp) returns records whose UpdatedDateUTC is later. Contacts: changes to balances, IsCustomer or IsSupplier do not trigger it. | SNIPPET | https://developer.xero.com/documentation/api/accounting/invoices ; https://developer.xero.com/documentation/api/accounting/contacts |
| Paging | Invoices: `page` alone returns 100 per call; `pageSize` can raise it (example 250). Paging invoices returns line items without per-invoice fetches. | SNIPPET | https://developer.xero.com/documentation/api/accounting/invoices |
| Webhooks | Signed with `x-xero-signature` (HMAC-SHA256 of raw body with signing key, base64). New subscriptions need "intent to receive" validation (four test POSTs: 2xx for the correctly signed one, 401 for the others). Payload carries event category/type and ResourceId, not the full record; fetch the resource afterward. Event categories documented include contacts and invoices (also prepayments, overpayments). | SNIPPET | https://developer.xero.com/documentation/guides/webhooks/overview/ ; https://developer.xero.com/documentation/guides/webhooks/subscriptions |
| Webhook response deadline / retries | Not confirmed. | UNVERIFIED | n/a |
| Entities | Accounting API includes Invoices (sales and bills via Type ACCREC/ACCPAY), Contacts (customers and suppliers), Payments, Accounts, Items, BankTransactions, ManualJournals, PurchaseOrders, Prepayments, Overpayments. | SNIPPET | https://developer.xero.com/documentation/api/accounting/invoices ; https://developer.xero.com/documentation/api/accounting/contacts |
| Sandbox | Xero provides a Demo Company for testing (resets, 28-day-style expiry reported by community). Not confirmed on an official page here. | UNVERIFIED | n/a |
| Idempotency keys | Not found in search; do not claim Xero supports idempotency keys. Design idempotency on our side. | UNVERIFIED | n/a |

## Implications for KRIVA copy

- We are an independent development team building against the public Intuit and Xero APIs. No partnership, certification, App Store listing or "official integration partner" language.
- Safe concrete claims: OAuth 2.0 with refresh handling; token expiry and re-authorization flows; webhook-plus-poll (CDC for QuickBooks, If-Modified-Since for Xero); per-tenant rate-limit-aware queues; sandbox / demo company testing before production; scoped access; production-key assessment for QuickBooks.
- Honest limitations to state: Xero 60 calls/min per organisation and 5000/day; QuickBooks about 500 requests/min per company; webhooks can miss edge cases so a scheduled reconcile is needed; refresh tokens expire if unused; Xero granular scope migration; Xero uncertified-app connection caps; QuickBooks Desktop is a different integration path.
