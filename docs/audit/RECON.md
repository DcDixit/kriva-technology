# KRIVA recon

Verified 2026-11-22 against the HTML/CSS/JS in this repo and against `npm run preview` at `http://localhost:5177` (Vercel rewrite map). Render checks used headless Chrome on that server. An item is REPRODUCED only when the current source or the rendered page shows it.

## Map

Static HTML site. There is no React, Next, or other app framework in `package.json` (`kriva-redesign`; runtime dependency is `nodemailer` for `api/inquiry.js`). Clean URLs are server rewrites, not a client router: `vercel.json` `rewrites` map `/about` to `kriva-about.html` (and the same pattern for every public page). `serve-preview.js` (`npm run preview`, port 5177) applies that map locally. Legacy `kriva-*.html` paths 301 to the clean URLs.

Styling is custom CSS, not Tailwind or a component library. Shared tokens and chrome live in `shared/tokens.css`, `shared/chrome.css`, `shared/kds.css`, `shared/inner.css`, `shared/system.css`, and `shared/responsive.css`. Page skins are `shared/*-x.css` (services, solutions, markets, work, insights, contact, about, process, pricing, cases). `shared/archetypes.css` is no longer linked. Its product-frame rules now live in `shared/inner.css`. Typeface is Figtree (`/brand/fonts/figtree-latin-var.woff2`).

Live content is inline HTML. There is no MDX and no CMS. Parallel data files under `content/` (`services-data.cjs`, `insights-data.cjs`, `cases-data.cjs`, `markets-data.cjs`, `seo-meta.cjs`, `page-labels.cjs`) and generators (`apply_chrome.cjs`, `_build_markets_x.cjs`, `build_*.cjs`) can disagree with the HTML that is actually served.

There is no shared layout component. Each `kriva-*.html` file is a full document. Header, mega-menu (`.mm`), mobile sheet (`#sheet`), and footer are copied into every page; `apply_chrome.cjs` is the generator and `shared/chrome.js` is only behavior (open/close, scroll).

## Risks

Chrome is duplicated, not imported. Header, mega-menu, sheet, and footer are pasted into every HTML file. `apply_chrome.cjs` is what last wrote that block (including the Canada-less sheet line and the service list that omits logo design and AI-assisted development). Editing one page, or editing only the generator and not re-applying it, will leave the other copies stale. Re-running the generator will overwrite per-page chrome tweaks.

The served page is the HTML file. `content/services-data.cjs`, `content/insights-data.cjs`, `content/cases-data.cjs`, `content/markets-data.cjs`, and the `build_*.cjs` / `_build_markets_x.cjs` scripts are a second source. They already disagree with the live pages (services data still titles web development "Web Design & Development"; insights data still says "a engineering team"; markets data omits Australia while the HTML page exists). Re-running those generators would put the old strings back.

`content/page-labels.cjs` and `shared/schema.js` feed llms, RSS, sitemap labels, and some JSON-LD names. They do not drive the visible nav. A nav rename will not update those files, and editing only those files will not change the header.

`shared/seo.js` writes the robots, googlebot, and bingbot metas into every head. Removing the duplicate on one page will not stick if that helper is reapplied. JSON-LD is also inlined per page, so breadcrumb names in the script can drift from the visible `.crumbs`.

Inquiry markup is copied onto most pages (`form.inq-form`, honeypot, `.inq-done`), with behavior in `shared/page-inquiry.js`. Contact is a separate pair of forms. A form-copy fix has two implementations.

There is no CMS. Nothing in the repo is fetched from a remote content system at request time. The risk is the generators and the duplicated HTML, not a locked CMS field.
