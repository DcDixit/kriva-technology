01 · Landing

Earn the signup without overselling the product

Clarify who it is for, what first value looks like, and what happens after the click. Vague hero copy kills activation before onboarding starts.

Design decisionLead with the job-to-be-done and one primary CTA. Defer feature inventory until after account creation.
02 · Account

Make account creation feel short and reversible

Collect only what you need to create a workspace. Password, SSO, and invite paths should feel like one continuous flow, not three products.

Design decisionProgressive fields with clear error recovery. Never force billing before first value unless the model requires it.
03 · Workspace

Name the workspace and set context early

Workspace setup is where multi-tenant products either feel personal or generic. Company size, role, and intent should shape the next screens.

Design decisionUse answers to route the first-run checklist, not to stall the user in a long questionnaire.
04 · Permissions

Clarify who can do what before the team arrives

SSO and role sprawl often push permission setup ahead of value. Make roles understandable in plain language and invite-ready.

Design decisionDefault safe roles, explain access in product language, and defer advanced admin until someone needs it.
05 · First value

Guide one meaningful action before the tour ends

Activation is not “completed setup.” It is the first outcome the user came for: a report, a record, an invite accepted, a sync that works.

Design decisionDesign the empty state as a path to value, not a blank canvas with a tooltip tour.
06 · Activated

Show progress and make the next step obvious

Checklists work when they map to real outcomes. Seat invites, first report, and billing should feel like momentum, not chores.

Design decisionSurface completion state in the shell so returning users know what is left without hunting.
07 · Retained

Design the return path as carefully as signup

Day-7 and day-14 returns depend on habit loops: scheduled value, clear notifications, and a home that reflects live work.

Design decisionInstrument activation events early so product and design share the same definition of “working.”
