## 2. Responsive issues by route and viewport

### H-1 Header logo and menu button invisible at the top of 4 pages (pre-existing, also live) [V]

| Route | 360 | 390 | 768 | 1440 | After scrolling |
|---|---|---|---|---|---|
| `/careers` | ✗ | ✗ | ✗ | ✓ | ✓ |
| `/technologies` | ✗ | ✗ | ✗ | ✓ | ✓ |
| `/services/graphic-design` | ✗ | ✗ | ✗ | ✓ | ✓ |
| `/services/seo-digital-marketing` | ✗ | ✗ | ✗ | ✓ | ✓ |
| All other 64 routes | ✓ | ✓ | ✓ | ✓ | ✓ |

- **What a visitor sees:** at the top of the page on phone or tablet, the header shows only "Book a call". The KRIVA logo and the menu (hamburger) button are white on white (pixel contrast 0). They reappear once the visitor scrolls and the header turns solid. The button still works and screen readers still announce it; it is a visual defect. Screenshot: `evidence/final/header/live/_services_graphic-design_768.png`.
- **Root cause (confirmed by experiment):**
  1. These pages use the dark-hero layout (`body.svx-moved`, hero `data-dark`). The header is transparent and the logo is filtered to white, expecting the dark hero to sit directly behind it.
  2. Their older page stylesheets force the mobile section-chips nav visible below 1281px: `shared/careers.css:263`, `shared/stack.css:553`, `shared/graphic-design.css:557`, `shared/seo-marketing.css:537` (`.mob-chips{display:flex !important}`). The chips sit **before `<main>`**, so they push the dark hero down.
  3. On the other 18 pages with this layout the chips are hidden, so the hero starts at 0 and the header is fine.
  4. The chip nav is also **duplicated** on these pages (M-1), which doubles the push-down: hero starts at 106–134 px instead of 0.
  - Experiment on a disposable copy: removing only the duplicate fixed `/careers` and restored the menu button on `/technologies`, but not the other two. Removing the duplicate is not enough on its own.
- **Live:** identical, 8/8 failures at 390 and 768 on krivatechnologies.com (`header_live_four.json`).

### No other responsive issues [V]
0 routes with horizontal overflow at any width; 0 hidden reveal content; 0 broken images.
